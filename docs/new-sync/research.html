⚙️ Code Generation Patterns

1. tRPC — Zero-Code-Gen Type Safety

How It Works

tRPC uses TypeScript's type system to infer types from procedure definitions. No code generation step required — types flow directly from server to client at runtime.

// Server: Define router with procedures
const appRouter = router({
  getUser: publicProcedure
    .input(z.object({ id: z.string() }))
    .query(async ({ input }) => {
      return await db.user.findUnique({ where: { id: input.id } });
    }),
  createUser: protectedProcedure
    .input(userCreateSchema)
    .mutation(async ({ ctx, input }) => {
      return await db.user.create({ data: input });
    }),
});

export type AppRouter = typeof appRouter;

✓ Pros

  • Zero code generation step
  • True end-to-end type safety
  • Excellent developer experience
  • No build step complexity

✗ Cons

  • Requires TypeScript
  • Server/client must share type imports
  • Doesn't generate REST endpoints
Relevance to Avileo: HIGH — tRPC's procedure-based pattern could define sync operations declaratively. The middleware pattern could handle common sync logic (conflict detection, idempotency, versioning).

2. Prisma — Schema to Client Generation

How It Works

Prisma uses a schema definition file and generates a type-safe client. The schema is the source of truth.

// schema.prisma
model Customer {
  id        String   @id @default(uuid())
  name      String
  email     String   @unique
  orders    Order[]
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}

// Generated client is fully typed
const customer = await prisma.customer.findUnique({
  where: { id: '123' },
  include: { orders: true }
});

✓ Pros

  • Schema as source of truth
  • Excellent TypeScript support
  • Migration management built-in

✗ Cons

  • Generated code can be large
  • Limited to relational databases
  • No built-in sync capabilities

3. Drizzle — TypeScript-First ORM

How It Works — Already Used in Avileo!

Drizzle uses TypeScript to define schemas directly in code. Types are inferred, not generated. This is what Avileo already uses.

import { pgTable, uuid, varchar, timestamp } from 'drizzle-orm/pg-core';

export const customers = pgTable('customers', {
  id: uuid('id').primaryKey().defaultRandom(),
  name: varchar('name', { length: 255 }).notNull(),
  email: varchar('email', { length: 255 }),
  businessId: uuid('business_id').notNull(),
  createdAt: timestamp('created_at').notNull().defaultNow(),
  updatedAt: timestamp('updated_at').notNull().defaultNow(),
});

// Types inferred at compile time — no generation step
export type Customer = typeof customers.$inferSelect;
export type NewCustomer = typeof customers.$inferInsert;
Key Insight: Drizzle's schema-first approach with type inference is the ideal foundation for a sync schema generator. We can add decorators to existing Drizzle schemas to generate sync artifacts.

4. Nexus (GraphQL) — Declarative Schema Definition

import { objectType, makeSchema } from 'nexus';

const Customer = objectType({
  name: 'Customer',
  definition(t) {
    t.string('id');
    t.string('name');
    t.string('email');
    t.list.field('orders', { type: 'Order' });
  },
});

export const schema = makeSchema({
  types: [Customer],
  outputs: {
    schema: './generated/schema.graphql',
    typegen: './generated/nexus.ts',

});

  • GraphQL benefits (introspection)
  • Strong typing end-to-end

✗ Cons

  • GraphQL overhead for mobile
  • No offline-first support

🔄 TanStack Query Sync Patterns

TanStack Query (formerly React Query) focuses on server state management and provides primitives for synchronization but doesn't implement sync logic itself. However, it provides excellent building blocks.

Key Primitives for Sync

1. Mutations with Optimistic Updates 
const useCreateCustomer = () => {
  const queryClient = useQueryClient();

  return useMutation({
    mutationFn: (newCustomer) => api.createCustomer(newCustomer),
    onMutate: async (newCustomer) => {
      // Cancel outgoing refetches
      await queryClient.cancelQueries({ queryKey: ['customers'] });

      // Snapshot previous value
      const previous = queryClient.getQueryData(['customers']);

      // Optimistically update
      queryClient.setQueryData(['customers'], (old) => [...old, newCustomer]);

      return { previous };
    },
    onError: (err, newCustomer, context) => {
      // Rollback on error
      queryClient.setQueryData(['customers'], context.previous);
    },
    onSettled: () => {
      queryClient.invalidateQueries({ queryKey: ['customers'] });
    },
  });
};
2. Background Synchronization 
const { data } = useQuery({
  queryKey: ['customers'],
  queryFn: fetchCustomers,
  staleTime: 30000,       // 30s before considered stale
  gcTime: 300000,         // 5min before garbage collected
  refetchInterval: 10000, // Refetch every 10s (polling)
  refetchOnWindowFocus: true,
});

Offline Mutation Queue Pattern

function useOfflineMutation(options: {
  queryKey: QueryKey;
  mutationFn: (data: T) => Promise;
  syncFn: (data: T) => Promise;
}) {
  const queryClient = useQueryClient();
  const [offlineQueue, setOfflineQueue] = useState([]);

  // Process offline queue when online
  useEffect(() => {
    if (!navigator.onLine) return;

    const processQueue = async () => {
      for (const item of offlineQueue) {
        try {
          await options.syncFn(item);
          setOfflineQueue((q) => q.filter((i) => i !== item));
        } catch (e) {
          break; // Will retry on next online event
        }
      }
    };

    processQueue();
  }, [navigator.onLine, offlineQueue]);

  const mutation = useMutation({
    mutationFn: async (data: T) => {
      if (navigator.onLine) {
        return options.mutationFn(data);
      } else {
        setOfflineQueue((q) => [...q, data]);
        return Promise.resolve();
      }
    },
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: options.queryKey });
    },
  });

  return { mutation, offlineQueueCount: offlineQueue.length };
}

TanStack Query Sync Relevance

High Relevance — TanStack Query is already used in Avileo. A new sync framework should integrate with TanStack Query's mutation system, using:
  • onMutate for optimistic local updates
  • onError for rollback and conflict notification
  • onSettled for cache invalidation after sync

Drizzle Limitations for Sync

Drizzle doesn't generate REST endpoints or tRPC routers

No Client Stubs

🏗️ Proposed Framework Architecture

Design Principles

1. Declarative

Define what to sync, not how

2. Schema-First

Generate boilerplate from Drizzle schemas

3. Type-Safe

End-to-end types, client + server

4. Minimal Runtime

Use existing TanStack Query + PGlite

import { syncEntity, syncField, conflictStrategy } from '@avileo/sync-generator';

@syncEntity({
  name: 'customers',
  table: 'customers',
  conflictStrategy: conflictStrategy.TIMESTAMP,
})
export class CustomerSyncSchema {
  @syncField({ primary: true })
  id: string;

  @syncField({ required: true, maxLength: 255 })
  name: string;

  @syncField({ maxLength: 20 })
  dni?: string;

  @syncField({ maxLength: 50 })
  phone?: string;

  @syncField()
  address?: string;

  @syncField({ sync: false })  // Not synced
  syncStatus?: string;

  @syncField({ version: true })  // For conflict detection
  updatedAt?: Date;
}

Generated TanStack Query Hook

// Generated: packages/app/src/generated/sync/hooks/use-customers-sync.ts

import { useMutation, useQuery, useQueryClient } from '@tanstack/react-query';

export function useCreateCustomer() {
  const queryClient = useQueryClient();

  return useMutation({
    mutationFn: async (data: CustomerCreate) => {
      customerCreateSchema.parse(data);
      return syncService.enqueue({
        entityType: 'customers',
        operation: 'create',
        entityId: crypto.randomUUID(),
        data,
      });
    },
    onMutate: async (newCustomer) => {
      await queryClient.cancelQueries({ queryKey: ['customers'] });
      const previous = queryClient.getQueryData(['customers']);

      queryClient.setQueryData(['customers'], (old: any[]) => [
        ...old,
        { ...newCustomer, id: 'temp-' + Date.now(), syncStatus: 'pending' }
      ]);

      return { previous };
    },
    onError: (err, newCustomer, context) => {
      queryClient.setQueryData(['customers'], context.previous);
    },
    onSettled: () => {
      queryClient.invalidateQueries({ queryKey: ['customers'] });
    },
  });
}
