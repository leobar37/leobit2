Propuesta de Arquitectura

Simplificación del Inventario

Una propuesta para eliminar la complejidad del sistema actual de inventario, separando claramente el stock de las distribuciones y reduciendo los múltiples modos a un solo flujo simple y predecible.

Sobre-ingeniería Detectada

El sistema actual tiene dos sistemas de modos superpuestos que crean una matriz de combinaciones imposible de razonar y mantener. Esto resulta en código muerto, confusion para los usuarios, y una curva de aprendizaje innecesariamente empinada.

Sistema 1: Modo de Operación del Negocio

Define como el negocio opera globalmente:

  • inventario_propio
  • sin_inventario
  • pedidos
  • mixto

Sistema 2: Modo de Distribución

Define como funciona cada distribución:

  • estricto - Reserva stock al crear
  • acumulativo - Similar a estricto
  • libre - Unico usado

Selector Oculto

El UI está hardcodeado a "libre". Los otros modos existen en el backend pero los usuarios no pueden accederlos.

Código Muerto

~300-500 líneas de código para reservas de stock, validaciones complejas, y transiciones de estado que nunca se ejecutan.

Complejidad Cognitiva

4 modos de negocio × 3 modos de distribución = 12 combinaciones posibles que los desarrolladores deben entender.

Código Actual - Hardcodeado create-distribucion-form.tsx 
// Modo is always 'libre' - hiding selector temporarily
const modo: ModoDistribucion = "libre";

// Submit handler - modo is hardcoded
const handleSubmit = async (data: DistribucionFormData) => {
  await createDistribucion({
    ...data,
    modo: "libre", // Siempre libre, los otros modos no se usan
  });
};

Propuesta: Un Solo Flujo Simple

Eliminar todos los modos y dejar un único flujo predecible: "Libre sin reservas". El stock se maneja independientemente, y los vendedores registran lo que llevaron al cerrar su distribución.

Principios Clave

  • 1
    Sin modos de distribución Un solo comportamiento predecible para todos
  • 2
    Stock separado Las distribuciones no manejan inventario
  • 3
    Registro al cerrar Vendedores indican lo que llevaron al final
  • 4
    Stock centralizado Un solo lugar para ver y ajustar inventario

Beneficios Esperados

  • -60% código de inventario
  • Curva de aprendizaje plana
  • Menos bugs por edge cases
  • Testing más simple y rápido

Flujo Simplificado

1. Crear Distribución

Sin seleccionar productos ni stock

2. Vender

El vendedor vende normalmente

3. Cerrar & Registrar

Indica productos llevados y vendidos

Comparación: Antes vs Después

Aspecto Antes (Complejo) Después (Simple)
Modos de Distribución estricto acumulativo libre Ninguno (único flujo)
Reserva de Stock Al crear distribución (modo estricto) No hay reservas
Validación en Ventas Depende del modo (complejo) Sin validación de stock (simple)
Cierre de Distribución Devolución de stock no usado Registrar lo llevado y vendido
Manejo de Stock Múltiples lugares (complejo) Solo en variant_inventory (simple)
Tablas de DB products, variants, inventory, distribuciones, items... Solo lo esencial (3-4 tablas)
Líneas de Código ~800-1000 (con modos) ~300-400 (sin modos)

Antes: Flujo Complejo

1. Admin crea distribución
2. Seleccionar modo (oculto)
3. Si es estricto: reservar stock
4. Validar stock en cada venta
5. Al cerrar: devolver sobrante

Después: Flujo Simple

1. Admin crea distribución
2. Vendedor vende libremente
3. Al cerrar: registrar productos llevados

El stock se ajusta manualmente por el admin en el panel de productos

Stock

Unificado en variant_inventory. El admin gestiona cantidades directamente.

Distribuciones

Solo tracking de estado y cierre. Sin lógica de stock.

Ventas

Independientes, referencian productos directamente.

Componentes del Sistema

ProductInventoryService

Gestiona todo el stock en un solo lugar. CRUD de cantidades, alertas de stock bajo, ajustes manuales por el admin.

updateStock() getStockAlerts() adjustInventory()

DistribucionService

Maneja el ciclo de vida de distribuciones: creación, asignación a vendedor, cierre con registro de productos. Sin lógica de stock.

create() closeWithItems() getActive()

SaleService

Registra ventas vinculadas a una distribución. Referencia productos directamente, sin validación de stock (el stock es referencial/administrativo).

create() getByDistribucion()

distribucion_cierre_items

Nueva tabla 
export const distribucionCierreItems = pgTable("distribucion_cierre_items", {
  id: uuid("id").primaryKey().defaultRandom(),
  distribucionId: uuid("distribucion_id").references(() => distribuciones.id),
  variantId: uuid("variant_id").references(() => productVariants.id),

  // Lo que el vendedor REGISTRA al cerrar
  cantidadLlevada: integer("cantidad_llevada").notNull(), // Cuanto llevo
  cantidadVendida: integer("cantidad_vendida").notNull(), // Cuanto vendio
  cantidadDevuelta: integer("cantidad_devuelta"), // Cuanto sobro

  // Calculado automaticamente
  montoVentas: decimal("monto_ventas", { precision: 10, scale: 2 }),

  createdAt: timestamp("created_at").defaultNow(),
});

Esta tabla reemplaza el concepto de "items" de distribución. El vendedor la llena solo al cerrar, indicando qué llevó y qué vendió.

Flujo de Trabajo Completo

1

Admin: Crear Distribución

El administrador crea una nueva distribución asignándola a un vendedor. No se seleccionan productos ni se reserva stock.

Datos requeridos:

  • • Vendedor asignado
  • • Fecha de asignación
  • • Notas de apertura (opcional)
2

Vendedor: Recibir y Vender

El vendedor recibe productos físicamente del admin (fuera del sistema) y comienza a vender. Las ventas se registran normalmente.

Recepción física

El vendedor recibe pollos/productos del almacén/admin

Ventas

Registra cada venta en la app móvil

3

Vendedor: Cerrar Distribución

Al final del día (o cuando termina), el vendedor cierra la distribución indicando exactamente qué productos llevó y cuánto vendió de cada uno.

Formulario de cierre:

Pollo Entero 1kg
Llevó: 10 Vendió: 8 Sobró: 2
Medio Pollo
Llevó: 5 Vendió: 5 Sobró: 0
4

Admin: Revisión y Ajustes

El admin revisa el cierre, compara con las ventas registradas, y ajusta el stock general según sea necesario.

Revisar cierre del vendedor

Comparar con ventas registradas

Ajustar stock si es necesario
