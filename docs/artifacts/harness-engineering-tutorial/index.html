AI Agents & Trust

Harness Engineering

Cómo construir confianza en código generado por IA. Un marco mental para separar lo que controlamos de lo que no.

Birgitta Böckeler & Martin Fowler · Abril 2026

1 El Problema: Confianza en IA

Los modelos de IA son no determinísticos, no conocen nuestro contexto, y no entienden realmente el código — piensan en tokens. ¿Cómo podemos confiar en lo que producen?

🌉

Analogía: El Puente Peatonal

Imagina un puente peatonal de cristal sobre un cañón. El vidrio es seguro el 99% de las veces... pero ese 1% te mata. ¿Caminarías sin mirar?

→ El código de IA es como el puente: probablemente funciona, pero necesitamos "arneses" (harnesses) por si algo sale mal.

2 ¿Qué es un Harness? (Arnés)

Harness = Todo en un agente de IA excepto el modelo itself.

En ingeniería, un "harness" conecta algo con algo más — como el arnés de un paracaídas. Nos permite controlar sin detener.

La Fórmula
Agent = Model + Harness

3 Los Dos Pilares: Guides y Sensors

Guides

Feedforward Controls · Antes de actuar

Anticipan el comportamiento del agent y buscan guiarlo antes de que actúe.

AGENTS.md (convenciones)
Skills (instrucciones de bootstrap)
MCP servers (conocimiento del equipo)
System prompts

Sensors

Feedback Controls · Después de actuar

Observan después de que el agent actúa y ayudan a auto-corregirse.

Linters (ESLint, Prettier)
Tests (unit, integration)
Mutation testing
AI code review

🚗💡 Analogía: Conducir un Auto

Guide = GPS

Te dice la ruta antes de que tomes una decisión mala. "Gira a la derecha en 500m" — anticipa.

Sensor = Espejos

Te muestran cuando te desviaste después de que ya ibas mal. "Te estás saliendo del carril" — corrige.

4 Dos Tipos de Ejecución

Los guides y sensors pueden ejecutarse de dos formas diferentes:

⚡

Computational

Determinístico y rápido

Velocidad ms - segundos
Confiabilidad 100% determinístico
Costo Barato

Ejemplos

Type checkers Linters Unit tests ArchUnit
🧠

Inferential

Semántico y probabilístico

Velocidad segundos - minutos
Confiabilidad Probabilística
Costo GPU = caro

Ejemplos

AI code review LLM as judge Semantic analysis

💡 Usa Computational siempre que sea posible — es más barato y confiable.
Usa Inferential solo cuando necesitas juicio semántico.

5 The Steering Loop (Ciclo de Dirección)

El trabajo del humano es dirigir (steer) el agent iterando sobre el harness. No es programar con el agent — es programar el harness.

💡 Concepto Clave

El agent no es tu programador. Es tu pair que te ayuda a construir las herramientas que te dan confianza en el agent.

Ejemplo: Un agent puede ayudarte a escribir tests estructurales, generar reglas de un patrón observado, o crear linters custom.

7 Las 3 Categorías de Regulación

🔧
Más fácil

Maintainability Harness

Confianza: Alta

Regula la calidad interna del código y mantenibilidad. Tenemos mucho tooling existente.

Computational Sensors

Linters Type checkers Coverage

Lo que NO detecta

Misdiagnosis Overengineering
🏗️
Media

Architecture Fitness Harness

Confianza: Media

Define y verifica características arquitectónicas. [Fitness Functions](https://www.thoughtworks.com/en-de/radar/techniques/architectural-fitness-function)

Ejemplos de Guides

Performance requirements Logging standards

Ejemplos de Sensors

Performance tests Debugging instructions
🐘
Más difícil

Behaviour Harness

Confianza: Baja

¿El código hace funcionalmente lo que necesitamos? Este es "el elefante en la habitación".

⚠️ Problema: Poner toda la fe en AI-generated tests "is not good enough yet".

Feedforward

Functional specification (de short prompt a multi-file)

Feedback

AI-generated test suite + manual testing

💡 Algunos equipos usan Approved Fixtures Pattern — más fácil en algunas áreas que otras.

🌱

Legacy

9 El Rol del Humano

"A good harness should not necessarily aim to fully eliminate human input, but to direct it to where our input is most important."

👤 Humano

  • ✓ Social accountability (nombre en el commit)
  • ✓ Aesthetic disgust (funciones de 300 líneas)
  • ✓ "We don't do it that way here"
  • ✓ Organizational memory
  • ✓ Small steps, human pace

🤖 Agent

  • ✗ No tiene nombre en el commit
  • ✗ No le importa el código feo
  • ✗ No sabe las convenciones locales
  • ✗ No tiene memoria organizacional
  • ✗ Piensa en tokens, no en significado

Key Takeaways

1

Agent = Model + Harness

El model es lo que no controlas. El harness es donde tú intervienes.

2

Guides + Sensors

Anticipar (feedforward) + Detectar/Auto-corregir (feedback). Ambos necesarios.

3

Computational > Inferential

Más barato, determinístico. Usa inferential solo cuando necesitas juicio semántico.

4

Behaviour es difícil

Maintainability = fácil. Behaviour = el problema abierto más grande.

5

Programa el harness, no el código

El steering loop es sobre mejorar controles, no sobre escribir código.

6

Keep Quality Left

Checks lo más a la izquierda posible — CI/CD y harness comparten esta filosofía.
