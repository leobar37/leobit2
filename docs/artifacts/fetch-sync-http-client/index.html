Avileo Sync Engine

FetchSyncHttpClient

Cliente HTTP que conecta la base local (PGlite) con el servidor backend. Gestiona el envío de operaciones, conflictos y sincronización offline-first.

Este componente está resaltado

Métodos Principales

sendBatch() async

Envía operaciones pendientes al servidor en batch. Cancela peticiones previas automáticamente.

POST /sync/batch AbortController
getConflicts() async

Obtiene lista de conflictos de sincronización con filtros opcionales (status, entityType).

GET /sync/conflicts Query params
getConflict(id) async

Obtiene detalle de un conflicto específico por su ID.

GET /sync/conflicts/:id
resolveConflict() async

Resuelve un conflicto: aceptar local, aceptar servidor, o merge con datos combinados.

POST /sync/conflicts/:id/resolve resolution + mergedData
abort()

Cancela cualquier petición HTTP en vuelo usando AbortController. Útil para cambios de pantalla o navegación.

Flujo de Sincronización

1. Usuario crea registro local

Vendedor crea un cliente o venta en la app (modo offline).

INSERT INTO customers (id, name, sync_status)
VALUES ('cuid_123', 'Juan Pérez', 'pending')

2. SyncService encola operación

Se agrega a la tabla sync_operations con metadata completa.

INSERT INTO sync_operations
(entity_type, entity_id, operation, payload, status)
VALUES ('customers', 'cuid_123', 'insert', '{...}', 'pending')

3. FetchSyncHttpClient envía batch

POST /sync/batch con todas las operaciones pendientes.

Headers: Authorization: Bearer {token} x-business-id: biz_123
Body: { operations: [...], deviceId, sourceFingerprint }

4. Backend procesa y responde

Servidor valida, aplica cambios y retorna resultados por operación.

{
  success: true,
  data: {
    results: [
      { idempotencyKey: '...', success: true },
      { idempotencyKey: '...', success: false, conflict: {...} }
    ]
  }
}

5. Actualización local

SyncService marca operaciones como synced o detecta conflictos.

ÉXITO
sync_status = 'synced'
CONFLICTO
sync_status = 'conflict'

Gestión de Conflictos

Versión Local

Datos creados/editados en el dispositivo del vendedor.

LocalVersion: 5

Conflicto Detectado

Ambas versiones modificaron el mismo registro simultáneamente.

ServerVersion: 7 > LocalVersion: 5

Versión Servidor

Datos oficiales en PostgreSQL (fuente de verdad).

ServerVersion: 7

Opciones de Resolución

Aceptar Local

Mantener cambios del vendedor, sobrescribir servidor.

Aceptar Servidor

Descartar cambios locales, usar versión oficial.

Merge Manual

Combinar ambas versiones mediante UI de resolución.

Headers de Seguridad

Header Valor Propósito
Authorization Bearer {jwt_token} Autenticación del usuario
x-business-id biz_xxx Multi-tenancy (tenant isolation)
x-correlation-id sync-{timestamp}-{random} Trazabilidad de operaciones
Content-Type application/json Formato de payload
