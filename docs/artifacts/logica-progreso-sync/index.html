🔍 Entendiendo la Lógica de Progreso

Cómo funciona el contador de sincronización en Avileo y por qué mostraba "0 registros"

🎯 El Problema

Pantalla mostraba:
"Ventas recientes: 0 registros"
"738 registros sincronizados"

El usuario veía 0 registros en el mensaje de etapa actual, aunque el total (738) era correcto. Esto era confuso porque el progreso estaba avanzando.

📊 Las 3 Etapas de Sincronización

La descarga de datos ocurre en 3 etapas secuenciales. Cada etapa hace un pull (petición) al servidor.

1️⃣ CRITICAL ✓ Completado
📦 Clientes, Productos, Variantes 📅 Últimos 30 días
⬇
2️⃣ RECENT_SALES ⏳ Cargando...
🛒 Ventas, Items de venta 📅 Últimos 7 días
⬇
3️⃣ HISTORICAL ⏸ Pendiente
📚 Abonos, Compras, Distribuciones 📅 Todo el histórico

📡 Cómo Llegan los Datos

El StagedPullCoordinator llama a un callback cada vez que hay progreso. Pero hay un timing importante:

Etapa 1: CRITICAL
callback: { stage: "CRITICAL", status: "loading", changesApplied: 0 }
↓
callback: { stage: "CRITICAL", status: "loading", changesApplied: 100 }
↓
callback: { stage: "CRITICAL", status: "complete", changesApplied: 400 }
Etapa 2: RECENT_SALES (INICIA)
⚠️ PROBLEMA AQUÍ:
callback: { stage: "RECENT_SALES", status: "loading", changesApplied: 0 }
El mensaje mostraba: "Ventas recientes: 0 registros"
Etapa 2: Continúa
callback: { stage: "RECENT_SALES", status: "loading", changesApplied: 50 }
↓
callback: { stage: "RECENT_SALES", status: "loading", changesApplied: 100 }
↓
callback: { stage: "RECENT_SALES", status: "complete", changesApplied: 338 }

⚖️ Antes vs Después

ANTES (Bug)
0
"Ventas recientes: 0 registros"
Usaba: state.changesApplied
(Valor de la etapa actual)
DESPUÉS (Fix)
738
"Ventas recientes: 738 registros"
Usa: totalChanges
(Acumulado de todas las etapas)

💻 La Solución en Código

El Problema (Código Antiguo)

// ❌ ANTES: Usaba el valor específico de la etapa coordinator.setOnProgress((state) => { // state.changesApplied = 0 cuando inicia una etapa const message = `Ventas recientes: ${state.changesApplied} registros`; // Resultado: "Ventas recientes: 0 registros" 😵 });

La Solución (Código Actual)

// ✅ AHORA: Acumula el total de TODAS las etapas let totalChanges = 0; // Total acumulado const stageTotals = new Map<SyncStage, number>(); coordinator.setOnProgress((state) => { // Calcula cuántos registros NUEVOS llegaron en este callback const previous = stageTotals.get(state.stage) || 0; const newChanges = state.changesApplied - previous; if (newChanges > 0) { totalChanges += newChanges; // Acumula! } stageTotals.set(state.stage, state.changesApplied); // Usa el TOTAL acumulado, no solo el de esta etapa const message = `Ventas recientes: ${totalChanges} registros cargados`; // Resultado: "Ventas recientes: 738 registros cargados" ✅ });

🧮 Cómo Funciona el Acumulador

🔑 Conceptos Clave

🎯 Por qué funcionó el fix:
  • state.changesApplied: Es el contador de la etapa actual. Empieza en 0 cada vez que cambias de etapa.
  • totalChanges: Es el acumulador global que suma todas las etapas. Nunca decrece.
  • stageTotals Map: Guarda el valor anterior de cada etapa para calcular el delta (nuevos cambios).
✨ Lección aprendida:
Cuando muestres progreso de un proceso multi-etapa, usa el valor acumulado global para mantener consistencia visual. Los usuarios esperan ver números que solo suban, no que se reinicien entre etapas.
