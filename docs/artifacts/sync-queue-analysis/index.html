Sync Queue — Análisis Visual

El sistema de cola que permite que Avileo funcione sin conexión a internet, guardando operaciones locally y sincronizándolas cuando vuelve la conectividad.

📦

Buffer local

Guarda operaciones pendientes en PGlite (IndexedDB) cuando el dispositivo está offline.

🔄

Replay después

Cuando hay conexión, envía las operaciones al backend en batches ordenados por prioridad.

⚡

Coalescing

Fusiona operaciones redundantes: múltiples updates se combinan en uno solo.

Problema que resuelve

Un vendedor ambulante necesita crear una venta mientras no tiene internet (en una zona rural, por ejemplo). La venta se guarda localmente con estado pending. Cuando recupera conexión, la cola envía la operación al servidor. Si el servidor reporta un conflicto (la misma venta fue editada desde otro dispositivo), la cola marca la operación como conflict. Si falla más de 5 veces, va a dead letter.

DLQ — Lógica duplicada

PgSyncQueue.moveToDeadLetter() y SyncService.moveToDeadLetter() hacen lo mismo. SyncService tiene su propia copia private del método y nunca llama al del queue. Si cambias la lógica del DLQ en el queue, el servicio sigue con la versión antigua.

🟡

Coalescing superficial

El merge hace { ...a, ...b }. Si un payload tiene items: [{id, qty}] y el segundo tiene items: [{id, qty, price}], el segundo reemplaza todo el array, no hace append por id. Para ventas con líneas de producto esto puede perder datos.

SyncService绕过队列边界

processPending() construye SQL directo en lugar de llamar a queue.getPending(). Esto rompe la abstracción: el servicio conoce los detalles de cómo ordenar por prioridad de entidad. Si cambias la prioridad, hay que tocar dos archivos en vez de uno.

Sin limpieza de completados

Las operaciones con status = 'completed' se quedan en la tabla para siempre. No hay método cleanupCompleted(before: Date). En un dispositivo que lleva meses funcionando, esto puede ser miles de filas innecesarias.

1

Eliminar DLQ duplicado

Hacer que SyncService llame a queue.moveToDeadLetter() en vez de su propia copia. Mover la lógica de self-heal a un wrapper del queue o a un interceptor.

// Antes (duplicado)
private async moveToDeadLetter(...) { /* 50 líneas */ }

// Después
await this.queue.moveToDeadLetter(op, error);
2

Deep merge para coalescing

Implementar merge recursivo para arrays de items. Identificar id como clave de fusión y hacer append+update en vez de replace total.

function deepMerge(a, b) {
  if (Array.isArray(a) && Array.isArray(b))
    return mergeById(a, b); // fusiona por id
  return { ...a, ...b };
}
3

Queue.getPending con prioridades

Mover la lógica de ordenamiento por prioridad de entidad al queue. El servicio solo dice "dame las siguientes N operaciones" y el queue sabe cómo ordenarlas internamente.

interface QueueOptions {
  priorityEnabled: boolean;
  groupEnabled: boolean;
}

await queue.getPending(limit, options);
4

Cleanup completado

Agregar un job que elimine operaciones completadas mayores a X días. Se puede disparar en el login o como cleanup nocturno.

async cleanupCompleted(
  olderThan: Date
): Promise<number> {
  const result = await this.pg.query(
    `DELETE FROM sync_operations WHERE status='completed' AND updated_at < $1`
  );
}
5

Re-export limpio de interfaces

No importar ISyncQueue directamente desde ./queue/sync-queue en sync-service.ts. Crear un barrel export en types/index.ts y que todos importen de ahí. Esto permite mover archivos sin romper imports.

6

Reemplazar console.log por syncLogger

En pg-sync-queue.ts, cambiar todos los console.log a syncLogger.debug/info que ya está disponible y es configurable.
