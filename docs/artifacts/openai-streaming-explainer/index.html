OpenAI API Deep Dive

Streaming de Chat Completions

Entendiendo text delta, tool calls, y cómo funciona el streaming en la API de OpenAI

1 El Concepto: Por qué existen los "Deltas"

Problema: Cuando pides una respuesta grande a GPT, no llega toda de una vez. Llega fragmento por fragmento (tokens).

✗ Sin Streaming

Esperas 5-10 segundos... luego aparece todo junto

✓ Con Streaming

Ves cada fragmento llegar en tiempo real (~100ms)

Cómo llega la respuesta "Hola mundo" (simplificado):

Chunk 1: "Ho"
Chunk 2: "la"
Chunk 3: " mun"
Chunk 4: "do"
✓ "Hola mundo"

2 ¿Qué es un "Text Delta"?

Delta = la diferencia (cambio) desde el último chunk. Es incremental — solo llega el texto que es nuevo.

1

Recibiste:

"Ho"

2

Recibiste:

"la"

(No "Hola", solo "la" — el delta)

3

Recibiste:

" mun"

(Incluye espacio: " mun")

4

Recibiste:

"do"

Código del ejemplo

const deltaText = extractTextFromContent(delta.content);
// "Ho", "la", " mun", "do"...

iterationText += deltaText;
// "H" + "o" + "la" + " mun" + "do" = "Hola mundo"

await onDeltaText(deltaText, iterationText);
// Callbacks para UI en tiempo real

3 ¿Qué son "Tool Calls"?

Tool Calls = Cuando el modelo decide llamar a una función/herramienta (como buscar en la web, ejecutar código, etc.)

Cómo funciona un tool call en streaming:

1

El modelo decide llamar una herramienta

Pero aún no tiene todos los argumentos...

2

Tool call empieza (incomplete)

id: "call_abc123", name: "get_weather"

arguments: "" (vacío todavía)

3

Argumentos llegan fragmento por fragmento

argumentsDelta: '{"ciudad":'
argumentsDelta: '"Lima", '
argumentsDelta: '"pais": "Peru"}'
4

Tool call completo

{"ciudad": "Lima", "pais": "Peru"}

💡 ¿Por qué llega en partes?

El modelo genera tokens uno por uno. No sabe de antemano todos los argumentos completos. Conforme va "pensando", va emitiendo caracteres/palabras. Por eso los argumentos llegan como argumentsDelta — cada chunk es una adición incremental al JSON.

4 Tu Código: Desglose Visual

A extractTextFromContent()

OpenAI puede devolver el contenido de dos formas:

1. String directo

"Hola mundo"

→ Se devuelve tal cual

2. Array de partes

[
  { type: "text", text: "Hola" },
  { type: "text", text: " mundo" }
]

→ Se extrae solo el .text

B Los 3 Callbacks (lo que hace la magia)

onDeltaText(deltaText, iterationText)

Se llama por cada fragmento de texto. deltaText = el fragmento nuevo. iterationText = todo lo acumulado.

→ Úsalo para mostrar texto en tiempo real en la UI

onToolCallStart(info)

Se llama cuando inicia un tool call. Informa el id y name de la función.

→ Úsalo para mostrar "Llamando a get_weather..."

onToolInputDelta(info)

Se llama por cada fragmento de argumentos JSON. argumentsDelta = el chunk nuevo. argumentsJson = JSON completo hasta ahora.

→ Úsalo para mostrar los argumentos construyéndose en tiempo real

C ¿Por qué una Map<index, state>?

Porque múltiples tool calls pueden llegar intercalados:

Ejemplo: 2 tool calls llegan en paralelo

Chunk 1: { tool_calls: [{ index: 0, function: { name: "get_weather", arguments: '{"ciu' } }] }
Chunk 2: { tool_calls: [{ index: 1, function: { name: "get_time", arguments: '{"zone":' } }] }
Chunk 3: { tool_calls: [{ index: 0, function: { arguments: 'dad": "Lima"}' } }] }
Chunk 4: { tool_calls: [{ index: 1, function: { arguments: '"America/Lima"}' } }] }

El index indica qué tool call es. La Map acumula el estado de cada uno independientemente.

5 Ejemplo Completo: Tool Call Completo

Cómo se construiría un tool call para get_weather("Lima", "Peru")

onToolCallStart

{ id: "call_abc", name: "get_weather" }

onToolInputDelta

{ argumentsDelta: '{"ciudad":', argumentsJson: '{"ciudad":' }

onToolInputDelta

{ argumentsDelta: '"Lima", ', argumentsJson: '{"ciudad":"Lima", ' }

onToolInputDelta

{ argumentsDelta: '"pais": "Peru"}', argumentsJson: '{"ciudad":"Lima","pais":"Peru"}' }

Tool Call Completo

{
  id: "call_abc",
  name: "get_weather",
  argumentsJson: '{"ciudad":"Lima","pais":"Peru"}'
}

→ Listo para ejecutar con JSON.parse()

6 ¿Por qué es importante entender esto?

⚡

UX en Tiempo Real

Puedes mostrar el texto mientras llega, no después de 10 segundos.

🔄

Tool Calls Interactivos

Mostrar "Ejecutando get_weather..." conforme los argumentos se construyen.

🛑

Cancellable

Puedes abortar el stream con AbortController sin esperar toda la respuesta.

💰

Tokens Eficiente

Puedes procesar parcialmente sin esperar todo para tomar decisiones.

📊

Progreso Visible

Barras de progreso, indicadores de "escribiendo..." para el usuario.

🔧

Debugging Fácil

Ver exactamente qué llega en cada chunk para investigar problemas.
