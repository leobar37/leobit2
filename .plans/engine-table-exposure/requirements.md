# Engine Table Exposure - Requirements

## Objective

Eliminate direct schema imports from `@avileo/shared` in frontend services by exposing all Drizzle tables through the `SyncClientEngine` as a typed `tables` property, accessible via `BaseService`.

## Scope

- **In scope**: Schema file generation, engine extension, BaseService update, custom service refactoring, generator update
- **Out of scope**: Backend changes, shared schema modifications, type removal from shared

## Functional Requirements

- `FR-001` - The engine must expose all sync-enabled Drizzle tables via a typed `tables` property
- `FR-002` - `BaseService` must provide `this.tables` access to all subclasses without constructor changes
- `FR-003` - All custom services must use `this.tables` instead of importing tables from `@avileo/shared`
- `FR-004` - Generated services must import tables from `~/lib/sync/drizzle-schema` (fixing broken path)
- `FR-005` - The `drizzle-schema.ts` file must be auto-generated by the code generator alongside other sync artifacts
- `FR-006` - Table types must be fully inferred (no `any` loss) when accessed via `this.tables`

## Non-Functional Requirements

- `NFR-001` - Zero runtime overhead: the `tables` property should be a simple object reference, not a factory
- `NFR-002` - Type safety must be maintained or improved (full Drizzle type inference)
- `NFR-003` - Backward compatibility: existing `engine.getDb()` usage continues to work
- `NFR-004` - No circular dependencies between engine, services, and schema

## Acceptance Criteria

- `drizzle-schema.ts` exists in `packages/app/app/lib/sync/generated/` and exports all tables
- `SyncClientEngine.tables` provides typed access to all tables (e.g., `engine.tables.customers`)
- `BaseService.tables` is accessible in all service subclasses
- `payment-service.ts` contains zero imports of table objects from `@avileo/shared`
- `sale-service.ts` contains zero imports of table objects from `@avileo/shared`
- `purchase-service.ts` contains zero imports of table objects from `@avileo/shared`
- `distribucion-service.ts` contains zero imports of table objects from `@avileo/shared`
- `customer-service.ts` contains zero imports of table objects from `@avileo/shared`
- `inventory-service.ts` contains zero imports of table objects from `@avileo/shared`
- Generated services compile without errors using `~/lib/sync/drizzle-schema`
- All modified services pass TypeScript type checking

## Constraints

- Must not break existing engine initialization or service registration
- Must maintain compatibility with `SyncClientEngineLike` interface
- Generated file must stay in sync with `@avileo/shared` schema exports

## Open Questions

- Should types/interfaces (e.g., `Customer`, `Sale`) also be re-exported from `drizzle-schema.ts` to further decouple from `@avileo/shared`?
- How should the generator discover the list of tables to export (hardcoded list, introspection, or config-based)?
