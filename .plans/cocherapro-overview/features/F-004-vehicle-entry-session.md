# F-004 — Vehicle Entry Session

## Objective

Support the daily operational flow for registering vehicle entry, listing active vehicles inside the garage, searching by plate, and preventing duplicate active plates.

## Status

planned

## Owner

unassigned

## Scope Boundaries

### In Scope

- Tenant-scoped parking session or vehicle-entry model.
- Plate normalization to uppercase.
- Vehicle type selection: Auto, Moto, Camioneta.
- Automatic entry timestamp.
- Active `dentro` list with elapsed time.
- Search by plate.
- Duplicate active-plate validation per business.

### Out of Scope

- Checkout/payment capture.
- Reports and dashboards beyond active list summary.
- Plate recognition/photo capture.
- Ticket printing.

## Verified Context

- No existing `cochera`, parking, plate, or vehicle session implementation was found.
- Tenant-scoped operational tables should include `businessId` and indexes.
- Backend service/repository methods must accept `ctx` first and filter by `ctx.businessId`.
- Frontend operational lists should use mobile-first cards and TanStack Query hooks.

## Assumptions

- A vehicle session represents an entry that is either `dentro` or `fuera`.
- The same plate can re-enter after the prior session is closed.
- Entry time is generated by the server to avoid device clock inconsistencies.
