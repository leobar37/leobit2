# T-002 Remove Snapshot Fields

## Objective

Remove `confirmedSnapshot` and `deliveredSnapshot` from all schema definitions, types, and references. These fields are confirmed write-only (no functional reads anywhere in the codebase) and represent dead code that the custom `SaleSyncHandler` populates unnecessarily.

## Requirements Covered

- `FR-007`

## Dependencies

- `T-001` (audit confirms no hidden consumers)

## Files or Areas Involved

- `packages/backend/src/db/schema/sales.ts` - Modify: remove `confirmedSnapshot`, `deliveredSnapshot` columns
- `packages/shared/src/schema.ts` - Modify: remove same columns from shared schema
- `packages/shared/src/index.ts` - Modify: remove from `Sale`/`Order` interface
- `packages/app/app/lib/services/sale-service.ts` - Modify: remove from local type definitions
- `packages/app/app/lib/sync/generated/schema.ts` - Modify: generated, will regenerate
- `packages/app/app/lib/sync/generated/schemas.ts` - Modify: generated, will regenerate
- `packages/backend/src/services/repository/sale.repository.ts` - Modify: remove from update field unions (`Pick<Sale, "confirmedSnapshot" | "deliveredSnapshot">`)
- `packages/backend/src/services/repository/sale.repository.ts` - Modify: remove `confirmPreOrder` method's snapshot creation logic (or remove the entire method per FR-016)
- `packages/backend/src/services/repository/sale.repository.ts` - Modify: remove `deliverPreOrder` method's snapshot creation logic
- `packages/app/e2e/mocks/factories/order.factory.ts` - Modify: remove snapshot fields from factory
- `packages/backend/src/seed/index.ts` - Modify: remove snapshot field references
- `packages/app/scripts/migrate-to-pglite.ts` - Modify: remove snapshot field mapping
- `packages/app/scripts/migrate-tanstack-to-pglite.ts` - Modify: remove snapshot field mapping
- `packages/app/scripts/rollback-migration.ts` - Modify: remove snapshot field mapping

## Actions

1. Remove `confirmedSnapshot` and `deliveredSnapshot` from `packages/backend/src/db/schema/sales.ts`
2. Remove same from `packages/shared/src/schema.ts`
3. Remove same from `packages/shared/src/index.ts` type interface
4. Remove same from `packages/app/app/lib/services/sale-service.ts` local types
5. Remove from `sale.repository.ts` update field unions (lines 194-195, 248-249)
6. Remove snapshot creation logic from `confirmPreOrder` method (lines 404-408)
7. Remove snapshot creation logic from `deliverPreOrder` method (lines 449-453)
8. Remove from `order.factory.ts` mock factory
9. Remove from `seed/index.ts`
10. Remove from migration scripts (field mappings and JSON field lists)
11. Regenerate PGlite schema: `bun run dev` or relevant generate command
12. Generate Drizzle migration: `cd packages/backend && bun run db:generate`

## Completion Criteria

- `grep -r "confirmedSnapshot\|deliveredSnapshot" packages/` returns zero results (excluding node_modules)
- `bun run build` succeeds for all packages
- TypeScript compilation succeeds (no type errors from missing fields)

## Validation

- `cd packages/backend && bun run build`
- `cd packages/app && bun run build`
- `rg "confirmedSnapshot|deliveredSnapshot" packages/ --type ts`

## Risks or Notes

- This requires a database migration to drop the columns from PostgreSQL. The migration should be generated by `bun run db:generate` after schema changes.
- Existing data in those columns will be lost. Since nobody reads them, this is acceptable.
- The generated files (`packages/app/app/lib/sync/generated/*`) will need regeneration after the shared schema changes.
